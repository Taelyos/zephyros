# Zephyros 0.1.0

> **Erratum, 2026-10-14.** Independent audits found statements below that are false or
> incomplete. The text is left as published; these corrections apply.
>
> - **"The Contractor never sees them" is false.** The Contractor reads the names of the
>   acceptance tests in the criteria of the contract; a test file the client keeps in its
>   repository is in the base the Contractor starts from; and `delivery.status` gave the
>   Contractor the whole evidence report, whose run output quotes the source of a failing test.
>   In 0.2.0 the Contractor's report leaves out the run output.
> - **Two defects of the verification were not stated.** A delivered module imported by an
>   acceptance test ran in the process that recorded the results and could rewrite them (ATK-22).
>   A test file that a criterion named but that the hub did not hold was taken from the delivery,
>   and could pass (ATK-16). Both are fixed in 0.2.0.
> - **The runs are shown without their operator.** The operator's part (requirements, approvals,
>   starting the instances) was played by an orchestrating agent, not a person, a Claude Opus 5.5
>   session in runs 2 and 3. Its model calls are not in the table below.
> - **"One authorised model at a time" understates the lock.** The code authorised one model,
>   DeepSeek V4.1 Flash, and no configuration could change it. In 0.2.0 the configuration alone
>   names the models (`gateway.models`).
> - **One verification kit only**: `tests`, for pytest.
> - **The page "a run with real models" was out of date.** It said the run was not exercised yet
>   and did not mention `ZEPHYROS_KIT=tests`, without which there is no verification runner and
>   every delivery ends in an error. The page is rewritten for 0.2.0.

The first release of Zephyros: a hub with no model in it that runs a software project between an
**Owner** side, which writes the contract and the acceptance tests and then judges, and a
**Contractor** side, which builds and delivers. On every delivery the hub replays the Owner's
tests in a sandbox, decides with fixed rules, and opens a pull request with an evidence report.
A human merges.

The idea it tests: **cheap models build; an independent verification, with no model in it,
decides.** An agent that writes the code and grades it too will tell you it works. Zephyros never
asks it.

This is an experimental release for one machine, Linux or macOS with Docker.

## What is in it

- **A versioned contract** (schema 1.1.0): requirements and constraints, each with its
  verification method, stories, acceptance criteria and links. Each side has its own rights; the
  P0 floor belongs to the operator. A change is proposed, read by whoever decides, and approved.
- **Acceptance tests that belong to the Owner side.** The Contractor never sees them, and a
  delivery that touches one is refused. A test file that no criterion names is flagged, since the
  gate never runs it.
- **Deliveries through a staging area** (git bundles), replayed in a sandbox with no network and
  canary tests of the hub's own.
- **The gate**: PASS, CONCERNS or FAIL from fixed rules (every P0, 90 % of the P1, 80 % overall),
  over requirements and constraints alike. What a test cannot show is judged by an inspection the
  Owner records, and the gate decides again.
- **An evidence report on every pull request**: base, head, contract and acceptance tests by
  digest, every test outcome, the rules applied, the cost, and flags such as a change to the
  client's own `CONTRACT.md`. The Owner's verdict is posted on the pull request, and its title
  follows the current decision.
- **Isolation**: one network and one guard per instance, a token per project and side, protected
  networks out of reach, a model gateway that holds the provider key and serves one authorised
  model, and a hash-chained log of every call and refusal.
- **A threat model of 93 attacks**: 59 have automated tests, most of them run as the attacker
  would; 25 wait for the next milestone (signed approvals, budget, dashboard, backups); 9 have no
  automated test yet. 2,400+ tests in all, 96 % coverage.

## Three runs with real models

DeepSeek V4.1 Flash on every side, through OpenCode Go, on small Python projects.

| Run | What was built | Result | Model calls | Tokens in / out | Cost* |
| --- | --- | --- | --- | --- | --- |
| 1 | steam-watch, new; a real Contractor, the contract written by the operator | the 17th delivery passed 4/4, after the run exposed bugs in Zephyros itself, fixed as it went | 106 | 5.9 M / 75 k | $0.94 |
| 2 | homelab-home, new, and steam-watch v2, in parallel; a real Owner and Contractor | 3 deliveries, PASS 9/9, 7/7 and 10/10; the Owner checked its own tests against 18 wrong implementations, all caught | 278 | 14.0 M / 336 k | $2.31 |
| 3 | homelab-home v1.1; a real Owner and Contractor | CONCERNS, two constraints awaiting inspection, then PASS once the Owner inspected the code; its verdict posted on the pull request | 173 | 23.3 M / 191 k | $3.6 |

\* Indicative, at the provider's list price ($0.15 per million tokens in, $0.60 out), before cache
discounts; the runs were covered by a flat subscription.

Each run found something the simulated suite could not, and each finding is fixed in this
release: an approver who could not read the proposal, a gate that ignored constraints, an Owner
who judged without seeing the code, a Contractor that rewrote the client's `CONTRACT.md`
unnoticed ([ADR 0020](../decisions/0020-the-owner-sees-and-records.md)); a provider error that
said nothing, conversations that grew to 188,000 tokens a call, a review after every turn, a test
file that never ran, a pull request title that kept the first decision.

## Getting started

```bash
git clone https://github.com/Taelyos/zephyros && cd zephyros
uv sync --locked
scripts/check.sh        # lint, types, unit and acceptance suites; no Docker needed
scripts/deploy.sh up    # hub and filter, operator channel on 127.0.0.1:8081, simulated model
scripts/deploy.sh call project.create '{"name": "demo"}'
scripts/deploy.sh down
```

Needs Docker, [uv](https://docs.astral.sh/uv/) 0.12.24 and Python 3.12. With a real model:
[a run with real models](../real-test.md).

## Known limits

- One machine, IPv4 only. Linux and macOS; not Windows.
- One authorised model at a time; the hub refuses to start with any other.
- The gate judges what the contract says, nothing more.
- Three real runs, all small Python projects: not a benchmark.
- Turns take minutes, and real runs cost tokens. No dashboard yet.
